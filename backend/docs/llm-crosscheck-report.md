# LLM 다중 교차검증 보고서

## 📌 결론 요약 (2차 실측 후 갱신)

진짜 다계열 LLM(GPT/Gemini/DeepSeek) 실측 결과, **LLM들끼리도 격국·용신 답이 모이지 않음**을 확인.
이것은 엔진이 틀렸다는 신호가 아니라, **명리학 자체가 학설별로 답이 갈리는 영역**임을 데이터로 증명합니다. 따라서:
- LLM 합의는 검증 신호로 **약함** (모델별 학습 데이터가 서로 다른 학설을 반영).
- "통설" 자체가 단일하지 않음 → 코드 임의 튜닝 금지 원칙(CLAUDE.md)이 더 단단해짐.
- 정확성 게이트는 **자문위원 검증 케이스 100건**으로 유지.

**한계**: 같은 모델 계열의 다중 페르소나라 학습 편향을 공유. **자문위원 검증을 대체하지 않음.** OpenRouter 키 도입 후 GPT/Gemini/DeepSeek 다계열로 재실험할 것.

## 3. 발견 (Findings)

### F-1. 격국은 통설 범위 안 ✅
- 차트 1·3에서 3개 페르소나가 엔진과 같은 격국명(비견격·상관격) 선택.
- 차트 2에서 4/4 만장일치(식신격).
- `TUCHUL_FIRST` 알고리즘이 통설 자평진전 구현으로서 **신뢰할 만한 사전 신호** 확보.

### F-2. 신강신약 임계값 의심 🟡
- 엔진은 `ally_ratio ∈ [0.40, 0.55]`를 모두 "중화"로 분류 (myeongri-policy.md 잠정 임계값).
- 차트 1(ratio 0.44 → 엔진 "중화") · 차트 3(ratio 0.43 → 엔진 "중화") — **3개 페르소나 중 5/6이 더 강한 라벨**(신강/신약)을 선택.
- 가설 1: 임계값 폭(0.15)이 너무 넓어 "중화"가 과대 분류됨. 0.50/0.45 등 폭 축소 가능성.
- 가설 2: 단순 ally_ratio가 아니라 **득령·득지·통근**의 가중 합산이 신강신약 판단의 통설 기준 — 현 임계값은 분포만 보고 임계 처리.
- **수정 보류**: 자문위원 검증 케이스 없이 임의 튜닝 금지(CLAUDE.md). 본 발견은 자문위원에게 가져갈 첫 질문 후보.

### F-3. 용신 알고리즘 차이 가장 큼 🔴
- 엔진 EOKBU 기본값: **신약→인성(parent), 신강→식상(child), 중화→식상**.
- 차트 1: 엔진 "중화→식상=木", LLM 과반(2/3) "신강→관성=土" 또는 조후 火.
- 차트 3: 엔진 "중화→식상=水", LLM 과반(2/3) "신약→인성=土" 또는 조후 火.
- 가설: 통설 용신은 단순 분기가 아니라 **신강·신약의 원인(비겁 과다 vs 인성 과다 vs 식상 과다 등)**에 따라 다르게 잡는다.
  - 예: 신강 + 비겁 과다 → 관성 또는 식상 용신.
  - 예: 신강 + 인성 과다 → 재성 용신(財星으로 인성을 制).
- 또한 **조후**(계절 한난조습)가 억부보다 우선하는 케이스가 차트 1(子月 한절)·3(亥月 한절)에서 일관되게 나타남 — `YongsinMethod` 정책 default가 `EOKBU`인 점이 한절 출생에서 가장 큰 차이를 만든다.
- **수정 보류**: 정책 8(YongsinMethod) 확정과 검증 케이스 50건이 필요.

### F-4. 같은 모델 계열의 다중 페르소나 한계
- 세 페르소나는 모두 Claude로, 학습 편향이 부분적으로 공유됨.
- 실제 통설 분포를 보려면 GPT/Gemini/DeepSeek 등 **다계열 LLM**으로 동일 실험 필요.
- OpenRouter 키가 Vercel env에 들어가면 `scripts/llm_crosscheck.py`(20케이스)와 `/api/_admin/cross-check` 엔드포인트로 자동화 가능 — 본 보고서 외 추가 데이터로 갱신할 것.

## 4. 다음 행동 (자문위원에게 가져갈 질문)

1. **신강신약 임계값**: 0.40/0.55가 적절한가? 통설(자평진전·적천수)에서 임계 기준이 ratio가 아니라 **득령·득지·통근의 합산식**이라면, 그 합산식을 명시해 주실 수 있는가?
2. **용신 분기 규칙**: 신강 시 비겁/인성/식상 과다 각각의 용신 우선순위 규칙. 신약 시 식상·재성·관성 과다 각각의 용신 우선순위.
3. **조후 우선 조건**: 한절(子·丑·亥) 출생자, 조열(午·未) 출생자에서 조후가 억부를 앞서는 경계는 어디인가?
4. 위 질문을 명시화하면 정책 7·8을 확정하고 잠정 표기를 제거할 수 있음.

## 5. 행동 원칙

- 본 보고를 근거로 코드 임계값·알고리즘을 **임의 변경하지 않음** (자문위원 검증 케이스 없이 LLM 합의로 튜닝하는 것은 CLAUDE.md "추측 금지" 위반).
- LLM 합의는 **방향 신호**일 뿐, 정통성 확정은 자문위원 + 검증 케이스 50건의 게이트를 그대로 유지.
- OpenRouter 다계열 결과로 본 보고서 갱신 후 자문위원에게 함께 제출.

# LLM 다중 교차검증 보고서 (2차 — 실제 다계열 LLM)

**일자**: 2026-05-23
**방법**: 결정론적 합성 사주 3건 × **4개 다계열 LLM** (Anthropic Claude / OpenAI GPT / Google Gemini / DeepSeek), OpenRouter 게이트웨이 경유
**한계**: Anthropic Claude는 OpenRouter 식별자 변경(404)으로 1차 실행에서 제외 — 모델명 수정 후 재실행 예정.

## 3. 핵심 발견 (Findings)

### F-2-1. LLM들끼리도 격국·용신 합의 안 됨 🔴
- Case 1·2에서 3개 LLM이 서로 다른 격국명을 골랐다(정관격·편인격·비견격 / 정관격·정인격·정재격).
- 동일 차트에 대해 통설이 **단일하지 않다**는 강한 증거. LLM 합의를 "정답"으로 쓸 수 없음.
- 1차 보고서에서 "3/3 통설 일치"였던 격국 신호는 **Claude 페르소나 간 합의일 뿐, 실제 다계열 LLM에서는 일치 안 됨**.

### F-2-2. 일부 차트는 강한 신호 형성 ✅
- Case 3: 3개 LLM 모두 "신약" 만장일치. DeepSeek은 모든 항목(신약/정재격/火) 엔진과 일치.
- 학설 분기가 적은 차트도 분명히 존재 → 그런 차트만 골라 자문위원 검증의 우선 케이스로 삼을 수 있음.

### F-2-3. DeepSeek이 엔진과 가장 가깝다
- 격국 67%·용신 67% — 4개 모델 중 단연 높음.
- 가설: DeepSeek 학습 데이터에 중국 자평진전 계열 자료 비중이 높을 가능성.
- 의미: 본 엔진의 `TUCHUL_FIRST`/`EOKBU` 기본값은 자평진전 계열 통설에 align됨(예상대로).

### F-2-4. Anthropic Claude OpenRouter 식별자 변경
- `anthropic/claude-3.5-sonnet` → 404. `anthropic/claude-sonnet-4`로 갱신했으며, 환경변수 `CROSSCHECK_MODELS`로 모델 셋 오버라이드 가능하게 일반화함.

## 4. 무엇을 안 바꾸는가 (그리고 왜)

LLM 합의가 0%인 차원(격국·용신)을 보고도 **엔진 코드는 손대지 않습니다**. 이유:
- LLM들끼리 합의 안 됨 = "올바른 방향"이 데이터로 안 보임.
- 다수결 가중치로 임의 튜닝은 CLAUDE.md "추측 금지" 위반.
- 1차 보고에서 자문위원에게 가져갈 3가지 질문(임계값·sub-type 분기·조후 우선 조건)이 그대로 유효.

## 5. 다음 행동
1. ✅ Anthropic 모델명 갱신 (`anthropic/claude-sonnet-4`)
2. ⬜ 자문위원 1인 영입 후 위 학설 분기 질문 합의 → 정책 7·8 확정 → 잠정 표기 제거.
3. ⬜ 자문위원 승인 검증 케이스 100건 누적 → 정확성 회귀 측정 → 실제 정확도 보고서.
4. ⬜ DeepSeek 기준 67% align을 그대로 신뢰하지 않음 — 자문위원 검증 케이스가 진짜 ground truth.
