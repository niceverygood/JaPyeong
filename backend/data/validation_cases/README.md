# 검증 케이스 작성 가이드 (자문위원·도메인 전문가용)

이 폴더의 `*.json` 파일은 명리 엔진의 **회귀 테스트 정답지**입니다.
엔진이 뽑은 결과를 여기 `expected`와 대조해 정확도를 측정합니다.

> **출시 게이트**: 검증 케이스 100건 이상이어야 정식 출시 가능
> (`RUN_GATE_CHECK=1 pytest tests/engine/test_harness.py`).

스키마 정의: [`backend/src/engine/schema.py`](../../src/engine/schema.py) · 작성 예시: [`_TEMPLATE.json`](_TEMPLATE.json)

---

## 1. 파일·ID 명명 규칙

- 파일명 = ID + `.json`. **소문자·언더스코어**.
- 형식: `case_NNN_source-slug.json`
  - `NNN` = 3자리 일련번호 (예: `001`, `042`).
  - `source-slug` = 출처 약칭 (예: `myeongyogang`, `japyeong-jinjeon`).
  - 예) `case_007_myeongyogang.json`, `case_023_jeokcheonsu.json`
- **ID는 파일 안 `id` 필드와 일치**해야 하며 전체에서 유일해야 합니다(하네스가 중복 검사).
- `_`로 시작하는 파일(`_TEMPLATE.json`, `_README` 등)은 하네스가 **건너뜁니다**(템플릿·메모용).

## 2. 출처(source) 권장 우선순위

`source` 필드는 **필수**입니다(트레이스 불가 시 검증 무의미). 신뢰도 높은 순:

1. **박재완 『명리요강』** — 검산된 예시사주 (페이지 표기: `명리요강 p.123`)
2. **박재완 계열 정통 자료** — 검증된 강의·정리노트
3. **고전 예시사주** — 『자평진전』·『적천수』·『궁통보감』 등에 실린 명조 (권/편 표기)
4. **자체 작성** — 자문위원이 손으로 계산·교차검증한 사주 (`자체 / 검증위원 OOO`)

> 출처가 모호하거나 한 곳뿐이면 `notes`에 검증 방법을 적어 두세요.

## 3. expected 필드 — 필수 vs 선택

`expected`의 **모든 필드는 선택**입니다. 검증하려는 항목만 채우면 됩니다(부분 검증 OK).

| 검증 단계 | 채울 필드 | 비고 |
|---|---|---|
| **8자 추출** (최우선, 100% 일치 요구) | `pillars.year/month/day` (+가능하면 `hour`) | 가장 많이 필요 |
| 일간·신강신약 | `day_master`, `day_master_strength` | strength 95% 기준 |
| 십성 분포 | `ten_gods_count` | 100% 일치 요구 |
| 격국 | `geokguk` | 90% 기준 |
| 용신 | `yongsin` (+`huishin`/`gisin`/`gushin`) | 85% 기준, 자문위원 검증 |
| 대운 | `daewoon_start_age`, `daewoon_direction` | |

- **사주 8자만 검증하는 케이스도 환영**합니다. 8자 정확도가 모든 것의 토대입니다.
- 한 케이스에 여러 항목을 채우면 그만큼 여러 모듈을 동시에 검증합니다.

### 작성 시 주의
- 천간/지지는 **한자 원문**으로 (`"丙"`, `"戌"`). 한글 독음·romanization 금지.
- `day_master_strength`는 `신강`/`신약`/`중화` 중 하나.
- `daewoon_direction`은 `forward`(순행)/`backward`(역행).
- `birth`에 `longitude`/`latitude`/`timezone`을 꼭 채워야 진태양시 보정이 검증됩니다.
- 음력 입력이면 `calendar: "lunar"` + 필요 시 `is_leap_month: true`.

## 4. 🚫 절대 금지

- **유명인·실존 공인의 사주 등록 금지.** 저작권·명예훼손·개인정보 리스크.
  연예인·정치인·기업인 등 식별 가능한 실존 인물 사주를 절대 넣지 마세요.
- `name`은 `"예시1"`처럼 비식별 라벨만. 실명 금지.
- 현대 명리서의 해설 텍스트를 그대로 복사 금지(저작권). 사주 데이터(8자·격국 등 사실)와 출처 표기만 사용.

## 5. 추가 워크플로 (PR + 자문위원 승인)

1. 새 케이스 파일을 이 폴더에 추가 (`case_NNN_*.json`).
2. 로컬 확인:
   ```bash
   cd backend && pytest tests/engine/test_harness.py -q
   ```
   → 스키마 검증·ID 중복 검사 통과 확인.
3. PR 생성. PR 설명에 **출처와 검증 방법** 요약.
4. **자문위원 1인 이상 승인** 후 머지.
   - 8자만 있는 케이스: 만세력 교차 확인.
   - 격국·용신 포함: 명리 전문 자문위원 검토 필수.
5. 머지 후 누적 100건 도달 시 출시 게이트 통과.

## 6. 정책 의존성 주의

검증 결과는 [명리 정책](../../docs/myeongri-policy.md)에 따라 달라질 수 있습니다
(예: 진태양시 균시차 포함 여부, 자시 분할). 정책이 확정되기 전 추가한 케이스는
정책 확정 후 재검토가 필요할 수 있으니, 경계 시각(자시·절입 전후) 출생 사주는
`tags`에 `경계`를 달아 두세요.
